底层逻辑
六条结构原则
1
只有一个真源：记忆图谱
Digest、洞察、主动卡、任务是图谱上的四个视图，不是四套产出。每张卡带 ↩ 回到原声。
2
一种闸门，不是两种"待确认"
确认目标 → 确认产出 → 确认发布，同一条琥珀闸门；只有最后一步弹"真实副作用"二次确认。
3
「待确认」也是记忆的写入口
点"确认"才入图谱，点"存疑"标为可证伪。AI 的不确定性不会悄悄变成事实。
4
实时通道的成本让用户看得见
「实时中 / 已省电暂停」常驻；短按不联网，长按才开会议模式。触发策略不是后台黑盒。
5
配置 = 教小谛，纠错即配置
首次教（朗读 3 句）· 随手教（改一个词入热词）· 深度教（听感 / 理解 / 行动 / 记忆）。响应规则挂在场景下。
6
成长值奖励闭环，不奖励录音量
BP 只在确认事实 / 采用产出 / 纠正转写时加分，与"不常开实时"的成本原则一致。

配置层
不做设置迷宫，做「教小谛」
首次教 · 1 分钟
朗读 3 句
同时完成声纹注册（"说话人 A"= 你）、口音校准、首批热词；选 2–4 个场景；从通讯录 / 日历导入专名。
随手教 · 最重要
纠错即配置
转写里改一个词 → 自动入热词并回训口音；观察卡点"不重要" → 训练噪音阈值。大多数用户永远不进设置页。
深度教 · 四层
听感 · 理解 · 行动 · 记忆
声纹 / 热词 / 语言 → 场景与响应规则 / 忽略规则 / 提示词 → 模型 / Skill / 目的地 → 人物卡 / 遗忘。
关键重构
响应规则挂在场景下，
不是全局开关
"客户通话" = 说话人分离 + 承诺句 → 待办 + 祈使句 → 建任务 + 反复诉求 → 观察 + 闲聊 → 忽略 + 外语 → 翻译 + 自己的提示词。
录音时小谛自动识别场景，也可一个 chip 覆写"这场按 X 处理"。全局只留忽略规则：口令「小谛别记」、私人时段、敏感信息打码。

Todo 发布 · 集成
目的地路由，Hermes 是通道不是目的地
系统日历 · 邮箱 · 飞书
待办 → 日历 + 提醒；邮件以你的名义、发送前必须预览；消息只 @ 任务里出现的人。
Notion
数据库「谛听 · 任务」；字段映射：标题 / 状态 / 截止 / 原声链接；默认单向推送，双向状态同步可选。
龙虾 OpenClaw
跑在你自己机器上的 Agent：Gateway + Token；转发类型（检索 / 整理 / 多步执行）；拿到的是意图 + 引用片段，不是全部记忆；结果必须回到待确认结果。
通道
Hermes 实时
只配三样：什么时候开（唤醒词 / 手动 / 外语 / 祈使 / 高风险）· 月度预算（16 h / 200 h）· 降级阈值（电量 < 20%、RTT > 400ms 回本地转写）。不常开，静音超时自动关；摘要 / 报告 / 记忆走批处理。
不变的底线：任何目的地的写入都发生在你点「采用」之后；外部 Agent 的执行结果必须回到谛听的「待确认结果」，不能直接对外。
