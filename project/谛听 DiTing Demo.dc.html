底层逻辑：我对原方案做的 6 处调整
  1. 只有一个真源：记忆图谱。原方案里 Digest、洞察、主动卡、任务是四套并列的产出。Demo 里把它们统一为"图谱上的四个视图"——所有卡都带 ↩ 回到原声 引用；「反复被提」「被忽略的提醒」直接由图谱的频次/冲突驱动（见 任务 › 小谛观察）。
  2. 一种闸门，而不是两种"待确认"。原状态机里"待确认（目标）"与"待确认结果"是两个词，用户学两次。Demo 用同一条琥珀闸门贯穿：确认目标 → 确认产出 → 确认发布；唯一区别是最后一步会弹"真实副作用"二次确认（任务详情 / 洞察 › 发布）。
  3. 「待确认」也是记忆的写入口。洞察页的待确认条不只是给人看：点"确认"才入图谱，点"存疑"标可证伪——AI 的不确定性不会悄悄变成"事实"。
  4. 实时通道的成本让用户看得见。实时录音页顶部常驻「实时中 / 已省电暂停」；短按=快速捕捉（不联网、不字幕），长按=会议模式。触发策略（§8）不再是后台黑盒。
  5. 硬件是入口，不是身份。设备管理里 MR20 与 Farosh 并列，配对页处理 SK&ERR（已被绑定）的重置引导，回填态在首页状态点 + 设备页进度双通道可见。
  6. 配置 = 「教小谛」，纠错即配置。不做设置迷宫：① 首次教（朗读 3 句同时完成声纹+口音+热词，选场景，导入专名）；② 随手教（转写里改一个词 → 自动入热词并回训；把待办划到忽略 → 训练规则）；③ 深度教（我的 › 教小谛，按 听感/理解/行动/记忆 四层）。响应模式挂在场景下而非全局开关——"客户通话" = 说话人分离 + 承诺→待办 + 祈使→建任务 + 闲聊→忽略 + 自己的提示词；录音页可临时覆写"这场按 X 处理"。Skill 注册里，发送/写入类永远走结果闸门，这条底线不可关。
  7. 日 / 周 / 月是三种动作，不是一份报告放大。日=整理（说了什么、漏了什么）；周=对表（承诺兑现表、反复被提的升降）；月=沉淀（主题聚成文档、决策回看、遗忘建议）。粒度越大 AI 越少转述、越多对表。入口：记录 › 周/月，周日首页自动出复盘卡。
  8. 记忆三层 + 引用即永久 + 四道噪音闸。原声 30 天 → 转写 1 年（未引用段落 90 天压缩为摘要）→ 图谱永久但有温度（180 天不出现即归档、不再提醒）。唯一例外规则：被任务/洞察/报告引用过的片段永不过期。噪音：设备 VAD → 场景忽略规则 → "三无句"不入图谱 → 人工"不重要"回训（我的 › 教小谛 › 记忆与遗忘）。
  9. Todo 发布 = 目的地路由，Hermes 是通道不是目的地。待办→日历+提醒、文档→Notion、邮件→邮箱、消息→飞书、多步执行→龙虾（OpenClaw，跑在你自己机器上的 Agent）。所有写入发生在「采用」之后；外部 Agent 的结果必须回到「待确认结果」。Hermes 只配触发条件、月度预算、电量/弱网降级（教小谛 › 目的地与通道）。
  10. 成长值奖励闭环而非录音量。BP 只在"确认事实 / 采用产出 / 纠正转写"时加分，避免"录得越多越好"的反向激励，与"不常开实时"的成本原则一致。
